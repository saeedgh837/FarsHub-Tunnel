# FarsHub Tunnel

**تونل معکوس (Reverse Tunnel) بین دو سرور لینوکس، برای عبور از NAT و فیلترینگ.**

نسخه ۱.۰.۴ · لینوکس x86-64 · یک باینری static بدون وابستگی · پنل وب دوزبانه ·
[WTFPL v2](LICENSE)

> **وضعیت:** لایه‌ی بیرونی (دستور `farshub`، نام‌گذاری، ساختار، config، systemd)
> برندسازی شده است. موتور اجرا `bin/farshub-core` هنوز build آپ‌استریم
> `github.com/musix/backhaul` است و **سورس آن در این مخزن نیست**. جزئیات در
> [ORIGIN.md](docs/ORIGIN.md).

## معماری

نقش‌ها برعکس تصور رایج است:

```
کاربران ──► [server]  ◄──── همیشه Dial ───── [client] ──► سرویس مقصد
            سرور خارج                        پشت NAT / فیلتر
            پورت‌ها را Listen می‌کند          هیچ پورتی Listen نمی‌کند
```

کلاینت یک Control Channel دائمی به سرور باز می‌کند. با هر اتصال کاربر به
پورت‌های سرور، سیگنالی روی این کانال می‌رود و کلاینت یک اتصال از استخر خود
مصرف کرده و ترافیک را به سرویس مقصد تحویل می‌دهد.

## راه‌اندازی

سه گام، روی **هر دو** سرور.

### ۱. گرفتن بسته

این لینک همیشه به آخرین ریلیز اشاره می‌کند؛ نسخه در آدرس نیست، پس لازم نیست به
خاطر بسپارید:

```bash
curl -fsSL https://github.com/saeedgh837/FarsHub-Tunnel/releases/latest/download/farshub-tunnel.tar.gz | tar -xzf -
```

پوشه‌ی `farshub-tunnel/` باز می‌شود. قبل از نصب، سالم بودن موتور اجرا را تأیید
کنید — باید `2f86ffb6ab33de43abfc606e12a8d972` باشد:

```bash
md5sum farshub-tunnel/bin/farshub-core
```

اگر `curl` نیست، `wget -qO- <لینک> | tar -xzf -` هم همین کار را می‌کند. کل مخزن
همراه با تاریخچه را هم می‌شود گرفت:
`git clone --depth 1 https://github.com/saeedgh837/FarsHub-Tunnel`

<details>
<summary><b>راه دیگر — ساخت بسته‌ی لوکال و انتقال دستی</b> (وقتی تغییری داده‌اید و نمی‌خواهید ریلیز بزنید)</summary>

```bash
sh scripts/release.sh
```

خروجی `farshub-tunnel.tar.gz` در پوشه‌ی والد مخزن است (حدود ۵٫۴ مگابایت).
اسکریپت قبل از ساخت، MD5 موتور اجرا را با [ORIGIN.md](docs/ORIGIN.md) و خط‌پایان
فایل‌های اجرایی را چک می‌کند و اگر نخواند، بسته‌ای نمی‌سازد.

```bash
scp farshub-tunnel.tar.gz root@SERVER_IP:/root/
```

</details>

### ۲. نصب

از داخل پوشه‌ی مخزن:

```bash
sudo ./bin/farshub install server
```

سمت کلاینت (ایران / پشت NAT) به‌جای `server` بنویسید `client`.

موتور اجرا در `/usr/local/libexec/farshub/`، دستور `farshub` در
`/usr/local/bin/`، کانفیگ در `/etc/farshub/` و یونیت systemd نصب می‌شود. کانفیگ
موجود بازنویسی نمی‌شود.

### ۳. توکن و راه‌اندازی

توکن بسازید و **در هر دو طرف عیناً یکسان** بگذارید:

```bash
farshub token
```

```bash
sudo farshub edit server
```

```bash
sudo farshub enable server
```

## پنل وب

پوشه‌ی `web/` یک پنل پایش ایستا و دوزبانه (فارسی RTL / انگلیسی LTR) است با دو تم
و بدون وابستگی به CDN: وضعیت تونل و گذردهی، نوار اجرا (نقش/ترانسپورت/مدت
کارکرد/گوروتین/نسخه)، KPI با نمودار، ترافیک به تفکیک پورت، منابع سیستم،
رویدادها، مشخصات سرور، و کارت پشتیبانی تلگرام.

پنل صریحاً نشان می‌دهد **روی کدام سمت تونل اجرا شده** (سرور یا کلاینت) — چون در
تونل معکوس کلاینت dial می‌کند و سرور Listen، که برعکس انتظار رایج است. موتور
اجرا نقش خودش را گزارش نمی‌کند، پس `farshub install` کنار پنل یک `panel.json`
می‌سازد که نقش، نسخه و مشخصات میزبان را نگه می‌دارد. اگر پنل «سمت اجرا نامعلوم»
نشان داد، همین فایل نیست:

```bash
farshub panel-meta server > /var/lib/farshub/web/panel.json
```

پیش‌نمایش محلی، بدون هیچ سروری:

```bash
python web/devserver.py --port 8770
```

### بالا آوردن پنل

`install` فایل‌های پنل را روی دیسک می‌گذارد ولی چیزی آن‌ها را سرو نمی‌کند.
`panel-up` بقیه‌ی کار را یک‌جا انجام می‌دهد — nginx، رمز، فایروال، `panel.json`:

```bash
sudo farshub panel-up --sniffer
```

رمز تصادفی ساخته و چاپ می‌شود. اجرای دوباره‌اش بی‌خطر است: رمز قبلی حفظ می‌شود
و قاعده‌ی فایروال تکرار نمی‌شود. برگرداندن همه‌ی این تغییرها (خودِ nginx می‌ماند):

```bash
sudo farshub panel-down
```

### نام کاربری و رمز

برای نام کاربری و رمز دلخواه، از همان اول:

```bash
sudo farshub panel-up --user admin --password MyPass123 --sniffer
```

همین دستور بعداً رمز را هم عوض می‌کند (`--sniffer` فقط بار اول لازم است):

```bash
sudo farshub panel-up --password NewPass456
```

| گزینه | پیش‌فرض | کار |
| --- | --- | --- |
| `--port N` | `8088` | پورتی که پنل روی آن دیده می‌شود |
| `--user NAME` | `farshub` | نام کاربری ورود |
| `--password PASS` | — | رمز دلخواه؛ ندهید رمز تصادفی ساخته و چاپ می‌شود |
| `--new-password` | — | رمز تصادفیِ تازه به‌جای حفظ رمز قبلی |
| `--web-port N` | `2060` | پورت داخلی موتور که پروکسی می‌شود |
| `--sniffer` | خاموش | روشن کردن sniffer تا جدول پورت‌ها پر شود |

سه نکته:

- رمز دست‌کم ۶ نویسه، و بدون `:` (جداکننده‌ی خط `htpasswd`) و بدون `'`.
- عوض کردن `--user` کاربر قبلی را **حذف نمی‌کند** و او همچنان می‌تواند وارد شود؛
  `panel-up` نامش را چاپ می‌کند. برای حذفش خط مربوطه را از
  `/etc/nginx/farshub.htpasswd` بردارید.
- `farshub panel` فقط توضیح می‌دهد و گزینه نمی‌گیرد. اگر به آن گزینه بدهید،
  دستور درستِ `panel-up` را پیشنهاد می‌دهد و با کد ۲ بیرون می‌آید.

⚠ ارتباط HTTP است، پس رمز رمزنگاری‌نشده رد می‌شود. برای دسترسی امن‌تر TLS
بگذارید یا به‌جای انتشار پورت از تونل SSH استفاده کنید:

```bash
ssh -N -L 8088:127.0.0.1:8088 root@SERVER_IP
```

این پنل **جای پنل داخلی موتور اجرا را نمی‌گیرد** — موتور HTML خودش را (با
برندینگ آپ‌استریم) روی `web_port` سرو می‌کند و stripped است، پس تزریق پنل به
داخلش عملی نیست. `panel-up` همان پنل داخلی را از بیرون بسته نگه می‌دارد و
به‌جایش این یکی را سرو می‌کند.

> **آموزش کامل پنل:** [docs/PANEL.md](docs/PANEL.md) — پنج کاری که `panel-up`
> می‌کند و دلیل هر کدام، کانفیگ nginx، سه منبع داده (`/stats`، `/data`،
> `panel.json`) و فیلدهای پذیرفته‌شده‌شان، چیدمان پنل، و روش افزودن زبان سوم.
> فهرست دقیق مسیرهایی که عوض می‌شوند در
> [docs/CLI.md](docs/CLI.md#panel-up-چه-چیزهایی-را-عوض-میکند).

## دستورها

```bash
farshub help
```

| دستور | کار |
| --- | --- |
| `install <سمت>` | نصب موتور، کانفیگ و سرویس |
| `enable` / `disable` | اجرای خودکار در boot + راه‌اندازی / لغو |
| `start` / `stop` / `restart` | کنترل سرویس |
| `status` | وضعیت سرویس و خلاصه‌ی کانفیگ (توکن نمایش داده نمی‌شود) |
| `logs [-f] [-n N]` | رویدادها؛ `-f` زنده |
| `config` / `edit` | نمایش (با توکن ماسک‌شده) / ویرایش کانفیگ |
| `token` | ساخت توکن تصادفی ۳۲ بایتی |
| `check` | بررسی سلامت نصب و هشدارهای امنیتی |
| `run <سمت>` | اجرای مستقیم در ترمینال، برای عیب‌یابی |
| `panel-up` / `panel-down` | بالا آوردن پنل وب با nginx و رمز / برگرداندنش |
| `panel` | توضیح پنل وب و گزینه‌هایش |
| `panel-meta [سمت]` | ساخت `panel.json` پنل (نقش، نسخه، مشخصات میزبان) |
| `version` / `support` | نسخه / راه ارتباط با پشتیبانی |

اگر فقط یک سمت روی ماشین نصب باشد، نوشتن `server`/`client` لازم نیست. هر دستور
ناشناخته‌ای هم عیناً به موتور اجرا پاس داده می‌شود. شرح کامل در
[docs/CLI.md](docs/CLI.md).

## پایش و عیب‌یابی

```bash
farshub status
```

```bash
farshub logs -f
```

`check` هشدارهای امنیتی همین README را روی نصب واقعی می‌سنجد و با وجود «خطا»
کد خروج غیرصفر می‌دهد، پس در اسکریپت هم قابل استفاده است:

```bash
farshub check
```

### دو نشانه‌ی رایج

- **لاگ کلاینت پر از `unexpected EOF` است و پنل سرور «Disconnected» می‌گوید،
  در حالی که سرویس‌ها در حال اجرا‌اند** — تقریباً همیشه یعنی `remote_addr`
  به‌جای IP سرور، به دامنه‌ای پشت پروکسی کلادفلر (ابر نارنجی) اشاره می‌کند؛
  پروکسی CF فقط HTTP را عبور می‌دهد و کانال کنترل تونل هرگز به سرور نمی‌رسد.
  IP مستقیم سرور یا یک رکورد DNS-only (ابر خاکستری) بگذارید. `farshub check`
  سمت کلاینت همین را خطا می‌دهد و `farshub status` هم IP حل‌شده را نشان می‌دهد.
- **بعد از `enable` هیچ‌کدام از پورت‌های `ports` در `ss -tlnp` نیست** — طبیعی
  است: پورت‌های کاربر فقط وقتی باز می‌شوند که کلاینت با موفقیت وصل شده باشد.

## کانفیگ

نام کلیدهای TOML داخل موتور اجرا کامپایل شده و **قابل تغییر نیستند**. فهرست کامل
و شرح هر کلید در [docs/UPSTREAM-BACKHAUL.md](docs/UPSTREAM-BACKHAUL.md).

transportهای پشتیبانی‌شده (استخراج از موتور اجرا): `tcp`, `tcpmux`, `utcpmux`,
`ws`, `wsmux`, `wss`, `wssmux`, `uwsmux`, `udp`, `quic`, `faketcp`, `tun`.
چهار مورد آخر در README آپ‌استریم مستند نشده‌اند.

## امنیت

- `token` و `transport` **باید در دو طرف عیناً یکسان باشند**، وگرنه تونل برقرار نمی‌شود.
- transportهای `tcp`، `tcpmux`، `ws`، `udp` **رمزنگاری ندارند**. برای رمزنگاری از
  `wss` یا `wssmux` با گواهی معتبر استفاده کنید.
- `web_port` پنل داخلی موتور را **بدون هیچ احراز هویتی** و روی همه‌ی
  اینترفیس‌ها باز می‌کند؛ آدرس bindش قابل تنظیم نیست. پیش‌فرض این مخزن `0`
  (خاموش) است و `farshub panel-up` هنگام روشن‌کردنش همان پورت را با فایروال
  از بیرون می‌بندد. اگر دستی روشنش کردید، خودتان ببندیدش.
- `pprof = true` مسیرهای `/debug/pprof/*` را روی `0.0.0.0:6060` بدون auth باز می‌کند.
  در production روشن نکنید.
- `log_level = "info"` مقدار توکن را در خطای mismatch لاگ می‌کند؛ پیش‌فرض `warn` است.
- موتور اجرا در استارت‌آپ پارامترهای sysctl **کل سیستم** را تغییر می‌دهد
  (`net.core.*`, `net.ipv4.tcp_*`) و RLIMIT_NOFILE را بالا می‌برد.
- پورت تونل (`bind_addr`) allowlist ندارد؛ در فایروال سیستم آن را فقط به IP
  کلاینت باز کنید.

`farshub check` همه‌ی موارد بالا را روی نصب فعلی می‌سنجد.
